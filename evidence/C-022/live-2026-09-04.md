## Found blocker (not closed, needs the operator's Google Cloud Console)

With network tracking active from page load, the actual Google Identity
Services iframe request fails:

```
GET https://accounts.google.com/gsi/button?...&client_id=175412711513-...
  -> HTTP 403
```

This is the request that renders/authorizes Google's own sign-in iframe for
this exact origin + client ID pair. A 403 here is Google's standard response
when the calling origin is not in the Client ID's **Authorized JavaScript
origins** list in Google Cloud Console — the app's own fallback button still
renders visually (so it isn't obviously broken to a quick look), but clicking
it would not complete a real sign-in.

**Fix needed** (operator action, Google Cloud Console → APIs & Services →
Credentials → this OAuth 2.0 Client ID → Authorized JavaScript origins): add
`https://sharefridge.vercel.app` exactly (scheme + host, no path, no trailing
slash) and save. Propagation is usually near-instant but can take a few
minutes.

