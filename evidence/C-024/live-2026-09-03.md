## Real sender-adapter failure + 404/410 cleanup, live

Adding a food item to the subscribed room fires the `queue_room_change` trigger, which queues a
delivery and the request handler dispatches it inline against the real subscribed endpoint
(`https://fcm.googleapis.com/fcm/send/<random-uuid>` — a syntactically valid but unregistered
endpoint, since no real browser ever created it). Google's real FCM responded with an actual
Gone/unregistered status, and the server correctly disabled the subscription:

```sql
select id,room_code,version,disabled_at from public.push_subscriptions where room_code='920020';
--  4548953a-1a58-4850-8394-74e8fa226d22 | 920020 | 2 | 2026-09-03 15:44:41.837476+00

select id,state,attempts,last_code,accepted_at from sharefridge_private.push_deliveries;
--  986b278c-4215-4642-a18a-47b9be403676 | disabled | 1 | HTTP_410 | (null)
```

`state='disabled'`, `last_code='HTTP_410'`, `disabled_at` set on the subscription, `version`
bumped, no `accepted_at` — this is the real expired-endpoint cleanup path from a real provider
response, not a mocked one.
